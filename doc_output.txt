ระบบสำรองและกู้คืนข้อมูลถูกพัฒนาตาม requirement ในเอกสารออกแบบ โดยใช้แนวทาง Manual Backup / Restore เพื่อให้ใช้งานได้บน Hosting ปัจจุบันโดยไม่ต้องพึ่ง cron job หรือ shell access            9.1 วิธีทำงานของ Backup            ผู้ดูแลกดปุ่มดาวน์โหลดไฟล์สำรองจากหน้าแอดมิน            endpoint api/system_backup.php จะดึงข้อมูลจากตาราง users, inventory, appointments และ staff_logs            ระบบรวมข้อมูลทั้งหมดเป็นไฟล์ JSON พร้อม metadata เช่น app_name, backup_version, exported_at และ exported_by            ไฟล์สำรองถูกดาวน์โหลดออกไปเก็บไว้ภายนอกระบบ            9.2 วิธีทำงานของ Restore            ผู้ดูแลเลือกไฟล์ JSON ที่เคยสำรองไว้ และกดปุ่มกู้คืนข้อมูล            ระบบอ่านไฟล์, ตรวจสอบความถูกต้องของโครงสร้าง backup และเช็กว่ามีตารางที่จำเป็นครบหรือไม่            PHP เปิด transaction แล้วลบข้อมูลเดิมตามลำดับ staff_logs → appointments → inventory → users            หลังจากนั้นจึง insert ข้อมูลกลับตามลำดับ users → inventory → appointments → staff_logs            ถ้ามีข้อผิดพลาด ระบบจะ rollback เพื่อป้องกันข้อมูลค้างบางส่วน            เมื่อกู้คืนสำเร็จ ระบบจะบันทึก event นี้ลงใน staff_logs อีกครั้ง            10. การติดตั้งและการนำขึ้นใช้งาน              การพัฒนาและ
